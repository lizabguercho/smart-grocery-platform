## 0.4.0 — 2026-11-18 — stage: error-analysis (experimental, not frozen)
- **Change (four, bundled; the lifecycle prefers one, see Findings):** (1) prompt: count + amount is one entry (package_count, amount, product noun as counted_item), scope per_item with a multiplication sign or amount-before-count, whole_package for count-before-amount; sha256 `7e53c0950aad2b89563c4458478a47a156902f289529368b16e9d9b7bfe94a23`, still no examples. (2) parser: lenient re-parse that escapes a quote between two Hebrew letters (the gershayim in `מ"ל`). (3) `units-v2`: alias `ליט` = litre (shared registry, so rules too). (4) evaluator: `counted_item` matches when the two nouns share a word. Guidelines `guidelines-v2.1`.
- **Why:** error analysis of test2 (now development data, see FROZEN.md): `counted_item` convention mismatch on multi-packs, count+amount split into two entries, all 7 invalid JSON caused by an unescaped `מ"ל`/`ק"ג`, `ליט` unresolved.
- **0.3.0 (intermediate, prompt only):** added the `N*M` multi-pack rule (per_item, package_count N). Dev unchanged (no multi-packs there). On test2 targeted titles scope F1 15 -> 52 %, unit 63 -> 75 %, exact titles flat 4/40. Predictions kept as `qwen_{dev,test2}_v0.3.0.jsonl`.
- **Evaluation (0.4.0):** dev: presence F1 91 %, exact 68/100, invalid JSON 1, scope F1 **44 %** (was 83 % in 0.2.0). test2: presence P/R/F1 89/92/90 %, exact 47/100, invalid JSON 1 (was 7 in 0.3.0), unit 75 %, role 76 %, scope 72 %; random 60: exact 42, targeted 40: exact 5. Latency 7.0 s/title (dev), 8.4 s/title (test2) on 16 GB M1 MLX 4-bit, about 43-70 generated tokens.
- **Findings:** (1) **Regression to fix first:** Qwen now writes `whole_package` on count-only entries (20 dev misses, 100 % of the dev scope drop); the gold has scope empty there. The new scope sentences leaked onto count-only entries; fix by stating the count-only exception inside the same bullet and by a deterministic post-parse rule (count-only entry: scope null). (2) The JSON repair works (7 -> 1 failures). (3) Exact titles on the targeted part are still 5/40; the remaining mismatches are mostly amount/unit on `N*M` and entry shape. (4) Four changes were bundled to save runs, so the individual effects were not isolated; treat the result as one experimental condition. (5) test2 is no longer independent: it was read for error analysis and informed 0.3.0/0.4.0.
- **Decision / next:** keep 0.4.0 as the experimental baseline; first fix finding (1); then the training-set + fine-tune plan (see research_log Next).

## 0.2.0 — 2026-11-14 — stage: error-analysis
- **Change:** prompt only (model, 4-bit MLX conversion, decoding, parser and evaluator unchanged). Rewritten zero-shot prompt, sha256 `b9d56bee8179f8fc8085dbe8031c1d1a151eb2f77b7a939e92a4c5799dd62ad0`, still **no examples** (see CONTRIBUTING, prompt rules). Adds: what is and is not a measurement; explicit count rule (package_count + bare counted_item, no amount/unit/role/scope); unresolved-unit and bare-number rule (no describes/role/scope); a definition of `capacity`; one entry per measurement; null policy. The v0.1.0 illustrative examples (including real-vocabulary nouns and a dimension pattern) were removed.
- **Why:** v0.1.0 findings: counts written as amount/unit, role/scope noise, false measurements.
- **Artifacts:** `src/measurement_extraction/prompts.py`; predictions `research/normalization/predictions/qwen_dev.jsonl` (v0.1.0 kept as `qwen_dev_v0.1.0.jsonl`). **Test predictions were not regenerated** and remain v0.1.0 (unscored); regenerate them only at freeze. Commit: see git log.
- **Evaluation:** dev, same 100 gold items. Presence P/R/F1 91/93/92 % (was 95/80/86); exact titles 66/100 (was 67, within noise); invalid JSON 3 (unchanged, same quote-escaping cause); false measurements on "none" 4 (was 2); role macro-F1 81 % (was 54), scope 83 % (was 57); package_count accuracy on matched 90 %, counted item 83 %; amount accuracy 54 % (unchanged).
- **Findings:** (1) the model still copies counts into source_amount/source_unit ("15 יח" → amount 15, unit יח) while now also filling package_count, so the amount field mismatches; prompting alone does not remove a redundant field, a deterministic post-parse normalisation or a schema without those fields for counts would. (2) Bare trailing numbers still get describes/role/scope (mass/contents) against guidelines. (3) New over-extraction: ranges (`7-9`), count words inside names, `10X`, a trailing `2`. (4) Quote-escape failures are unchanged: the prompt cannot fix them. (5) The dev gold contains no capacity, per-item, multi-entry or count+amount items, so role/scope improvements are measured on near-trivial labels. (6) Prompt was iterated once against dev; one more round would start to fit dev.
- **Decision / next:** stop prompt iteration on this dev set. Next version (0.3.0) is a single non-prompt change: lenient JSON re-parse / grammar-constrained decoding, reported as a separate condition; then a count-entry normalisation. Before more prompt work, enlarge gold with items that exercise capacity, per-item and multi-pack.

## 0.1.0 — 2026-11-01 — stage: error-analysis
- **Change:** first full baseline inference. Zero-shot prompt (no demonstrations), prompt sha256 `69de49c2c3270a6086900578c16c9ecbe0723c09ea2e5e95a3bcaaa969405096`. Model `Qwen/Qwen3.5-4B` revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`, run as a local uniform 4-bit MLX conversion (group size 64, mlx-lm 0.32.2). Greedy decoding, `enable_thinking=False`, max 256 new tokens, one attempt per title, batch size 4.
- **Why:** baseline for the A/B/C comparison. 4-bit MLX because bf16 PyTorch on a 16 GB M1 ran at 14–19 s/title and swapped; MLX 4-bit runs at about 4.4 s/title.
- **Artifacts:** `src/measurement_extraction/{qwen,prompts}.py`; predictions `research/normalization/predictions/qwen_{dev,test}.jsonl`; a partial bf16 run is archived as `qwen_bf16_dev_partial.jsonl` (32 dev titles, not scored); guidelines `guidelines-v1`; commit: 239a32c.
- **Evaluation:** dev, 100 saved gold items. Presence P/R/F1 95/80/86 %; exact titles 67/100; 3 invalid-JSON failures (counted as misses); 2 false measurements on "none"; role macro-F1 54 %, scope 57 %; amount and package count accuracy on matched entries 57 %; counted item 89 %.
- **Findings:** (1) on count titles it writes the count into source amount/unit and leaves package_count empty, then adds role/scope; (2) it does not escape the quote in `מ"ל`/`ק"ג`, which breaks strict JSON; (3) one prompt line (JSON-escape instruction) was added after a 5-title smoke test and before this run. Presence recall on 24-character (truncated) titles is 93 %.
- **Decision / next:** v0.2.0 prompt engineering aimed at (1); the quote escaping stays a measured failure (a lenient re-parse can be a separate condition).
